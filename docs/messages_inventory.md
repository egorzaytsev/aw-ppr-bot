# Опись сообщений бота Пепе (@awprojects_bot)

Состояние кода: ветка oct20-cards, коммит 0648c22 (08.11.2026). Только чтение: код и Airtable не менялись. Боты @hareworldbot (сбор Telegram) и карточки испанского — вне описи.

Префиксы ID: ADM — admin.py (карточки и кнопки проверяющего); ADMM — сообщения админу из main.py; DLR — партнёру; CMD — команды; SYS — по расписанию и системные; ERR — ошибки; ENG — экраны анкеты; CRD — карточки решений (cards.py); REM — напоминания; ALR — алерты; PHR — пулы фраз.

Примеры с реальными данными: заявки AOF / Aylar Mamedova по PVSMART InsaitBC FL3 `AW260250` и SHANSGK `AW260248` (06.11.2026) — карточки, звонок, «Дополнить», повышение. В таблице приведены шаблоны дословно; живые примеры этих сообщений — на скриншотах в переписке с Егором 06.11.

## 1. Карта сценариев

Обозначения: ID — строка из таблицы ниже. ⛔ — тупик или петля, ⚠️ — проблема на шаге.

### 1.1 Новая заявка (уведомление → предрегистрация → регистрация)
1. Дилер: «Новый проект» → бот: анкета ENG-01, ENG-02 (вопросы — приложение A), гейты ENG-12/13/14/15 → итог ENG-16/17 → «Отправить».
2. Бот → дилер: DLR-25 (если есть файлы), DLR-27 («Информацию по проекту получили…» + maybe_egor).
3. Бот → админ: ADMM-03 (карточка ADM-09: все ответы, звонок сверху) + ADMM-04/ADM-10 (если выбран звонок).
4. Админ «✅ Принять» → ADM-30 (комментарий или «Отправить без комментария») → при совпадениях ADM-34 (в какой проект) → для нового проекта ADM-37/ADM-47 (название латиницей), ADM-14 (похожая компания) → для пошаговой проверки ADM-01 «Шаг 1 из 3».
5. Бот → дилер: DLR-30 (CRD-01…07 «✅ Заявка принята»); админ: CRD-13/ADMM-11 («Взято в работу»).
6. Если цель выше уведомления: бот → админ SYS-04 «Шаг 2 из 3» (ADM-01/02) → «Повысить» → DLR-30; после предрегистрации — «Шаг 3 из 3».
7. Админ «❌ Отклонить» → ADM-31 → (повышение без проекта) ADM-48 → бот → дилер DLR-35 / DLR-31.
- ⛔ ADM-01/02: на шагах 2–3 нет «Отказать»; при «Пока оставить» дилер, просивший регистрацию, ничего не узнаёт.
- ⚠️ ADMM-09/10: заблокированное решение приходит админу на английском, с именами полей Airtable, часто без кнопок.
- ⚠️ ENG-25 (VAGUE_HINT): «нажми кнопку под вопросом», но на обязательных вопросах фазы 1 кнопки нет — петля до /cancel.
- ⚠️ ENG-11 / ENG-23: подтверждение уровня контакта без файла — петля «Нужен файл или ссылка».
- ⚠️ ENG-12: после «Да» на гейте 1 необязательные вопросы фазы 1 теряют кнопку пропуска (engine._no_skip).

### 1.2 Повышение статуса (партнёр сам запрашивает)
1. Дилер: «Мои проекты» → DLR-16 (карточка: «✔️ Условия для предрегистрации выполнены», кнопка «⏭ Запросить предрегистрацию») или «Обновить проект → Запросить…» DLR-05/DLR-14.
2. Бот → дилер: DLR-21 (подтверди) → DLR-22 («Запрос … отправил Егору»). Если не готов — DLR-20 (чего не хватает) / CRD-14.
3. Спор за регистрацию (у других партнёров есть предрегистрация) → анкета материалов (приложение A, project_fill с _contested) → запрос уходит вместе с файлами.
4. Бот → админ: ADMM-03 с ADM-08 («Что есть в проекте», журнал целиком).
5. Админ «✅ Принять» → DLR-30; «❌ Отклонить» → DLR-31 (плейсмент остаётся уведомлением).
- ⚠️ DLR-20: `next_step_body(p.fields, "")` вызывается с пустым дилером — предрегистрированному пишет «Для перехода на предрегистрацию».
- ⚠️ ADMM-10: блокировка повышения — только английские имена полей и совет «Reg Status или /upgrade».

### 1.3 Повышение статуса (по инициативе бота)
1. Утром 9:00 → бот → админ SYS-08 «✔️ Условия для предрегистрации выполнены» → ADM-02 «⬆️ Повысить» / «Пока оставить» (ADM-19).
2. «Повысить» → DLR-30 дилеру, CRD-13 админу. Блок → ADMM-10.
- ⛔ «Пока оставить» — дилер не узнаёт, что условия выполнены.

### 1.4 Дополнение по проекту
1. Дилер: «Обновить проект → Дополнить материалы» (DLR-05) → выбор проекта DLR-14.
2. Бот → дилер: ENG-01 «Не хватает: …» и только эти вопросы; если ничего не не хватает и этап доступен — DLR-18 («Запросить предрегистрацию» / «Добавить материалы»); иначе вопрос о материалах с кнопкой «Новых материалов нет» → ENG-35 / DLR-24 (ничего не отправлено).
3. Итог ENG-16/18 → «Отправить» → DLR-27 → админ ADMM-03 («📝 Дополнение по проекту», все изменения).
4. Админ «✅ Принять» → DLR-34 (CRD-12 «Информацию внесли в проект») + админу CRD-13; если условия этапа выполнены — SYS-08 «Повысить?».
5. «❌ Отклонить» → DLR-35.
- ⚠️ «Пока не знаю — пропустить» теперь пропускает только вопрос; пропущенное снова попадает в «Дозаполнить» (ENG-37).

### 1.5 Новость / ответ на запрос информации
1. Дилер: «Обновить проект → Сообщить новость» → вопрос «Что нового?» → DLR-27 → админ ADMM-03 («📰 Новость…»).
2. Админ «Принять» → DLR-34 (CRD-11). «Отклонить» → DLR-35.
3. Запрос информации: кнопка «📨 Запросить у дилера» (ADM-06/29, готовый текст) или ADM-38/ADM-32 (свой текст) → DLR-36 с кнопкой «Ответить» → дилер отвечает → админ ADMM-03 («💬 Ответ на твой запрос») → решение по исходной заявке (ADM-26).
- ⛔ ADMM-11: ответ на «Need more info» при принятии закрывается молча — ни дилер, ни админ не получают подтверждения.
- ⚠️ ADM-29: готовый текст запроса уходит дилеру без показа админу; одна подпись «Запросить у дилера» в ADM-06 и ADM-38 означает разные действия.
- ⚠️ На карточке новой заявки кнопки «Спросить партнёра» больше нет (только Принять/Отклонить) — запрос информации доступен только из заблокированных решений.

### 1.6 Квотация (упрощённая схема, до 30 000 € по прайсу)
1. Дилер: в анкете ENG-15 «Номер квотации есть» или в карточке DLR-16 «🧾 Прислать номер квотации» → «Номер квотации?» → DLR-27.
2. Админ → «Принять» → DLR-33 (CRD-10 «Квотация № … зафиксирована»).
- ⛔ «Номер квотации?» обязателен, выхода нет, кроме /cancel (теряются все ответы); ENG-12 пишет «Сначала дополним», хотя дозаполнения нет.

### 1.7 Выигран / проигран
1. Дилер: карточка «Выигран» / «Проиграл» → короткая анкета → DLR-27 → админ ADMM-03.
2. Админ «Принять» → DLR-32 (CRD-09 «Информацию приняли — итог по проекту подтвердит Егор»).
- ⛔ Итог (Won/Lost) нигде не записывается и следующего шага нет.

### 1.8 Звонок
1. Дилер выбирает слот в анкете (Call Slot 15 / 30) → админ: строка 📞 в ADM-09 + отдельное ADMM-04/ADM-10 с кнопками.
2. «✅ Подтвердить» → ADM-17 дилеру, ADM-18 админу. «🕑 Другое время» → ADM-16 → админ пишет → ADM-42 дилеру, ADM-43 админу.
3. Бот → админ: SYS-06 (9:00, звонки сегодня), SYS-07 (≈ за час).
- ⚠️ ADM-18 «Напомню за час»: напоминание приходит по всем звонкам из заявок, подтверждение нигде не сохраняется (calls_confirmed только в памяти и не читается).
- ⚠️ ADM-42: «напиши Егор напрямую» — падеж имени.

### 1.9 Истечение срока / откат
1. 9:00 → админ SYS-05 «⏳ Истёк срок статуса — продли или откати» → ADM-22 → ADM-23 (причина) → DLR-38 дилеру + ADMM-08 админу.
- ⛔ Кнопки «Продлить» нет — продление только через Airtable; дата в формате гггг-мм-дд.
- ⚠️ ADM-23 без кнопки «Отмена».

### 1.10 Напоминания и сводки
- Дилеру: SYS-10 / REM-01…05 (еженедельно в выбранный слот), SYS-11 (брошенная анкета), SYS-12 (задержка ответа 72 ч).
- Админу: SYS-13 (ждёт решения > 48 ч, карточка без разбиения), SYS-14 / ALR-02 (сводка 9:00), ALR-01 / ERR-02 (ошибки раз в минуту).
- ⚠️ SYS-12 и DLR-27 «Егор» — дилерам Лолы тоже пишется «Егор».
- ⚠️ SYS-13 длинная карточка без разбиения — отправка может упасть, а метка late:48 уже стоит; при пропуске метки 48 ч карточка не уходит никогда.
- ⚠️ REM-01 «напоминание по твоим проектам» — по правилу «плейсмент», а не «проекты».

### 1.11 Незнакомый пользователь
1. Человек пишет боту → DLR-01/02 (его нет в списке) → админ ADMM-01 «👋 Новый человек в боте» (попросить Claude внести).
2. Внесли в People → SYS-01 человеку, SYS-02 админу. Нет за 7 дней → SYS-03 админу.

### 1.12 Команды и меню
- Дилер: CMD-01 (меню «/»), CMD-04/05/06 (/start), CMD-08 (/cancel), DLR-03 (незаконченный диалог закрыт), DLR-04/05.
- Админ: CMD-02/03, CMD-10…16 (/admin, /reminder, /inbox → ADM-11…13, /upgrade → ADM-04/05/20/22).

## Приложение B. Кнопки проверяющего (действия callback)

- `acc` (ACTION_ACCEPT) — принять: компании (ADM-14), пошаговая смена типа на New — Notification; при Target Project → проверка пустых ответов / переименование / Decision = Accept — merge into Target Project; без проекта → выбор проекта (ADM-34).
- `dec` (ACTION_DECLINE) — отклонить: ждёт причину (ADM-31), затем Decision = Decline + Decision Note.
- `inf` (ACTION_INFO) — свой вопрос дилеру: ждёт текст (ADM-32), затем Decision = Need more info + Decision Note.
- `pick` (ACTION_PICK) — принять в выбранный проект: Decision = Accept — merge, Target Project.
- `new` (ACTION_NEW) — принять в новый проект: запрос названия (ADM-37) → создание Projects + Decision = Accept.
- `cancel` (ACTION_CANCEL) — сбросить ожидание ввода (Bot Processed), «🛠 Отменено.»
- `remind_user` (ACTION_REMIND_USER) — не кнопка: ожидание username для предпросмотра напоминания (main.preview_reminder).
- `dpick` (ACTION_DPICK) — после отказа в пред/рег.: записать Target Project для фиксации уведомлением.
- `dnew` (ACTION_DNEW) — после отказа: создать новый проект (запрос названия ADM-35) и записать его в Target Project.
- `ask` (ACTION_ASK) — отправить дилеру готовый запрос недостающего (Decision = Need more info, Note = ask_text).
- `name` (ACTION_NAME) — взять предложенное латинское название для new/dnew.
- `accn` (ACTION_ACCEPT_NOTE) — «✅ Принять» на карточке: ждёт комментарий (ADM-30), затем как `acc`.
- `decn` (ACTION_DECLINE_BARE) — отказ без комментария (пустая Decision Note).
- `cok` (ACTION_CALL_OK) — подтвердить звонок: сообщение дилеру (ADM-17) и админу (ADM-18); в Airtable ничего.
- `cot` (ACTION_CALL_OTHER) — предложить другое время: ждёт текст (ADM-16) → дилеру (ADM-42).
- `up` (ACTION_UP) — повысить менеджера в проекте без заявки → main.upgrade_status (синтетическое решение, карточки дилеру и админу).
- `upno` (ACTION_UP_NO) — «Пока оставить» / «Отмена» в меню статусов → ADM-19.
- `upl` (ACTION_UP_LIST) — страница списка /upgrade.
- `ups` (ACTION_UP_PICK) — выбрана пара проект+менеджер → меню статусов (ADM-20).
- `pickf` / `accf` / `newf` (FORCE) — те же pick/acc/new с подтверждением «да, несмотря на пустые ответы».
- `dpn` / `dpp` / `dpa` (DOWNGRADE) — принять регистрацию как предрегистрацию: Request Type → … Pre-registration, автокомментарий (ADM-36), затем newf/pickf/accf.
- `ren` (ACTION_RENAME) — взять транслит как новое название проекта для слияния (Projects.Name), затем Decision = Accept — merge.
- `co` (ACTION_COMPANY) — выбрать компанию из базы или «новая» для клиента/бюро: Payload._Company Picks, затем продолжение решения.
- `rb` (ACTION_RB) — меню отката статуса (ADM-22).
- `rbd` (ACTION_RB_DOWN) — понизить на этап: ждёт причину (ADM-23) → main.rollback_status(mode=down).
- `rbc` (ACTION_RB_CANCEL) — снять статус: ждёт причину (ADM-23) → main.rollback_status(mode=cancel).
